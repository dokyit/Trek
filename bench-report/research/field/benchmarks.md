## What this means for a Trek benchmark
- Harness results (Terminal-Bench, SWE-bench, AA) measure the agent CLI, not the desktop app. Trek runs vendor CLIs, so its task score should equal the vendor CLI's, and a test should confirm that. What Trek adds is its prompt overhead (ADEMark's token tests) and app cost (ADEMark's speed and weight tests).
- Same-model harness gaps are real but small, and the sources disagree. On Opus 5.5, Claude Code scores 65.8 on the official 4.1 board and 57.6 in Factory's own Terminal-Bench 4 run. The "40x tokens" spread between harnesses (arXiv 2607.22585) shows that overhead matters more than pass rate.
- The only published "many agents" numbers are ADEMark's typing lag with 5 agents streaming, memory under load, and memory per thread from 5 to 20, plus Factory's 5 subagents taking more than 2 GB. I found no other benchmark of many parallel agents or tabs.

## Not found or not verified
- Terminal-Bench 2.0 and 3.0 entry lists on tbench.ai, which shows only 4.1. That means no dated Warp, Goose, Amp, Gemini CLI or Terminus entries from the official site. The figures of 82.0 for Codex on 2.0 and 77.3 for Droid on an unstated version are snippets only.
- Multi-SWE-bench, SWE-bench Live, GSO, Context-Bench, SWE-Lancer, and current Aider polyglot.
- Vendor harness claims from Warp, Amp, Cline, Kilo or Crush in 2026.
- Any independent RAM or startup comparison of Conductor, T3 Code, the Codex app, Claude desktop and Cursor, other than ADEMark.
- Two token claims, both snippets I did not read in full: "Claude Code 33k vs OpenCode 7k at session start" (Systima, Jul 2026) and The New Stack's "70x token variation".
- Accessibility reviews of Zed, the Codex app or Claude desktop.
