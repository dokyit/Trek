What it is

What Trek is

Trek is one place for the coding agents you already use. You see which are working, which are waiting on you and which have finished, and you answer from your desk or your phone. It is a native app, written in Rust and drawn on the GPU. Not Electron.

Opening and memory were measured on 5 November 2026 on a MacBook Air (Apple M5, 24 GB, macOS 27.2) with a release build: 186 to 201 ms from starting the app to its first frame, warm, and a footprint of 55 to 57 MB 25 seconds after launch, with none to 100 threads. The Mac was not idle during the runs, and only a scripted agent was running. The download is the Apple silicon disk image of version 0.4.49. The method, every number and the command that repeats them are in docs/PERFORMANCE.md.

How it works

From the first prompt to finished work.

Needs youAnswered

  1. Agents set off

    Start a thread for each piece of work. Each one is an agent working on its own, and several run at once.

  2. One stops and asks

    When an agent needs an approval, an answer or a plan reviewed, it waits. Its thread goes to the top of your Inbox with the reason in words.

  3. You answer

    Allow, deny or reply at your desk or from your iPhone, and the agent carries on from where it stopped.

  4. Work comes back to one place

    Finished threads land in the same Inbox, unread until you have looked at what was done.

The Inbox

What needs you comes first.

The sidebar is an inbox. Threads waiting on an approval, a question or a plan sit at the top, each with the reason in words. A failed turn, failing checks and a sub-agent that is asking are there too. Under them is work that finished while you were elsewhere, unread until you open it.

⌘⇧I steps through whatever needs you (Ctrl+Shift+I on Windows). The menu bar icon and Dock badge on a Mac, and the tray icon and taskbar badge on Windows, say whether Trek is idle, working or needs you.

  • Needs youAn approval, a question or a plan to review
  • FailedA turn that ended in an error
  • WorkingWith how long it has been at it
  • FinishedUnread until you open it

Agents and models

The agents you already use, with the logins you already have.

Trek drives each vendor's own command-line tool, so your subscriptions work as they do in the terminal. Trek never reads or stores those credentials. Install and log in to the agents you use, and Trek finds them on your PATH.

AgentsThrough each one's own CLI
Claude Code, Codex, OpenCode, Cursor, GitHub Copilot, Factory Droid, Kimi, Qwen Code, Grok, Devin, Goose, Amp, Pi and any agent that speaks the Agent Client Protocol.
API keysKept in the system keychain
Anthropic, OpenAI, Gemini, OpenRouter, DeepSeek, xAI, Mistral, Groq and any OpenAI-compatible endpoint.
Local modelsOn your own machine
Ollama, LM Studio, llama.cpp, MLX.

API and local models get Trek's own tools to read, edit, write and run, behind the same approvals. And agents can consult each other: ask one to review another's plan, and read its answer in the thread.

Trek for iPhone

Answer from your iPhone, while the agents keep working at your desk.

The agents keep running on your computer. The phone is the inbox and the remote: every thread and its status, approvals, questions and plans, steering a running turn, starting new threads, Notes and voice input.

It pairs with a QR code and connects straight to your computer over your Wi-Fi or Tailscale, with a pinned TLS certificate. No Trek server sits in between. Push notifications go through ntfy, if you turn them on.

For now you build the iPhone app yourself. It is built from source in Xcode and needs iOS 26. It is not on the App Store. How to build it.

For iOS developers

An agent can use your app on a real iPhone.

On a Mac, plug your iPhone in and it appears beside the chat: its screen, its apps and its files. You can tap and type on the picture, and so can the agent. It can install a build, open the app, tap, swipe and type, and look at what happened.

Seeing the screen and moving apps and files needs nothing on the phone. Taps go through a small driver that is built with Trek's iPhone app (it needs Xcode and Developer Mode), or over Bluetooth, or through macOS's iPhone Mirroring.

The iOS Simulator is beside the chat too. The agent boots a device, installs and launches your app, reads the screen as an outline of elements and taps them by reference, and runs your tests with each result shown in Trek.

Mac only. The iPhone and Simulator tools are part of Trek for macOS.

Permission rules

Say once what an agent may do.

Every thread has one of four levels, from Supervised, which asks before every edit and command, to Full access, which is off until you allow it. Plan mode makes the agent show a plan before it changes anything.

Rules sit on top of the levels. Each is a command, a file edit, a web fetch or a tool, set to allow, ask or deny. Deny wins, then ask, then allow, and a deny holds even at Full access.

A command rule reads a line the way a shell would, so a rule for rm also catches echo y; rm x. A line Trek can't read counts as matching a deny. The tester shows which rule decides and what happens at each level.

From an approval card, Always allow writes the rule for you, and you can edit it first.

Also in the app

Everything else stays beside the thread.

  • Undo any turn

    Each turn lists the files it changed. Review them, or undo the turn. Edit, retry or fork a message and the files roll back with it.

  • Notes that stay

    A Markdown notebook that persists, with pictures, videos and files, and a preview beside what you write. It is on the iPhone too.

  • Basecamp

    Today, this week or all time across every agent: what needs you, what is ready for review, and turns, tokens, failures and agent time.

  • iPhoneiOS 26, built from source

    Build instructions GitHub

    Open ios/Trek.xcodeproj in Xcode 26 or later and run it on your phone.

Then your agents. Install and log in to the ones you use: claude, codex, opencode and the rest. Trek finds them on your PATH, and setup offers to install the ones you are missing.

Questions

Asked before the download.

Is it another Electron app?

No. Trek is written in Rust and drawn on the GPU with GPUI. On an M5 MacBook Air it opens in about 0.2 seconds and idles at 55 MB of memory. The measurements and their conditions are on this page, and the command that repeats them is in the repository.

Is it free?

Yes. Trek is free and open source under the Apache-2.0 licence. You go on paying the makers of your agents as you do today; Trek uses the logins and API keys you already have.

What does it send anywhere?

Your prompts and code go where they already go: to the agents and model providers you choose, through their own tools or your API keys.

Trek asks once whether it may share anonymous usage data. With a yes it sends counts (how often Trek opens, which agents and tools are used), crash and error reports, and the app version, OS and architecture. It never sends prompts, code, file names, paths, transcripts, keys or account emails. With a no it sends nothing, except feedback you choose to send. You can change the answer in Settings, Privacy, which also shows exactly what was sent last.

Trek also checks GitHub for its own updates and public package feeds for new versions of your agents' CLIs. The iPhone app talks straight to your computer, and push notifications go through ntfy only if you turn them on. The privacy page has all of it.

Which agents does it run?

Claude Code, Codex, OpenCode, Cursor, GitHub Copilot, Factory Droid, Kimi, Qwen Code, Grok, Devin, Goose, Amp and Pi, and any agent that speaks the Agent Client Protocol. It also runs models directly: with API keys for Anthropic, OpenAI, Gemini, OpenRouter, DeepSeek, xAI, Mistral, Groq or any OpenAI-compatible endpoint, and locally through Ollama, LM Studio, llama.cpp or MLX.

Does it run on Windows?

Yes: Windows 11 on x64, with an installer and a portable .zip. A tray icon and taskbar badge take the place of the Mac's menu bar icon and Dock badge, and every command is in the palette (Ctrl+K). There is no iOS Simulator tool on Windows. Windows 10 22H2 works on a best-effort basis, and there is no Linux build yet.

How do I get the iPhone app?

For now you build it from source: clone the repository, open ios/Trek.xcodeproj in Xcode 26 or later, run it on your iPhone (iOS 26), then pair it in Settings, Phone & Machines. It is not on the App Store or TestFlight. The build instructions are in the repository.

Do I need an account, or new API keys?

No. Trek has no account of its own. It drives the agent CLIs you have already logged in to, so your subscriptions work as they do in the terminal, and it never reads or stores those credentials. API keys are only for providers you choose to add, and they are kept in the system keychain.
